BLOC 1 - Support et Mise à Disposition de Services Informatiques

Recueil des Besoins

Le recueil des besoins est la phase fondamentale qui précède tout projet informatique. C'est le processus de collecte et de documentation des exigences du client ou des utilisateurs.

Méthodes de Recueil

1. Les Interviews
  • Questions ouvertes et fermées avec les parties prenantes
  • Identification des contextes et contraintes
  • Échange direct et création de relation de confiance
2. Les Questionnaires
  • Formulaires standardisés envoyés à un large public
  • Questions préécrites et réponses mesurables
  • Adaptation facile aux différents groupes d'utilisateurs
3. Les Ateliers (Workshops)
  • Réunions de groupe avec brainstorming
  • Idées collaboratives et débat en temps réel
  • Consensus plus rapide entre parties prenantes
4. L'Observation
  • Observation directe du contexte de travail
  • Identification des problèmes non verbalisés
  • Compréhension des workflows réels
💡 Exemple : Pour un projet de digitalisation d'une PME, on organise : interview avec direction (stratégie), questionnaire aux opérateurs (usabilité), atelier avec managers (processus), observation des postes de travail (contraintes matérielles).

Analyse de Faisabilité

Faisabilité Technique

Évaluation des capacités technologiques à réaliser le projet :

Points clés :
  • Compatibilité avec l'infrastructure existante
  • Disponibilité de technologies appropriées
  • Risques techniques et mitigation
  • Compétences internes vs recrutement
  • Délais réalistes de développement

Faisabilité Financière

Analyse du budget et du retour sur investissement :

Éléments de coût :
  • Coûts d'acquisition (licences, matériel, infrastructure)
  • Coûts de mise en œuvre (intégration, configuration)
  • Coûts de formation du personnel
  • Coûts de maintenance et support annuels
  • Comparaison : ROI = (Bénéfices - Coûts) / Coûts × 100%

Faisabilité Organisationnelle

Capacité de l'organisation à accueillir le changement :

Critères :
  • Acceptation par les utilisateurs et management
  • Impact sur l'organisation et les processus
  • Ressources humaines disponibles
  • Risque de résistance au changement

Critères de Choix d'une Solution

Open Source vs Propriétaire

Open Source Propriétaire
✓ Avantages :
  • Coûts de licence réduits
  • Code source accessible
  • Communauté active
  • Pas de dépendance fournisseur
 ✓ Avantages :
  • Support professionnel assuré
  • Interface intuitive
  • Maintenance garantie
  • Mises à jour régulières
✗ Inconvénients :
  • Support communautaire inégal
  • Documentation parfois incomplète
  • Expertise requise
  • Maintenance interne nécessaire
 ✗ Inconvénients :
  • Coûts de licence élevés
  • Dépendance au fournisseur
  • Code source fermé
  • Licence restrictive

On-Premise vs Cloud

On-Premise (Local) Cloud
✓ Avantages :
  • Contrôle total des données
  • Infrastructure personnalisée
  • Pas dépendance internet
  • Sécurité localisée
 ✓ Avantages :
  • Accès de n'importe où
  • Pas de maintenance interne
  • Scalabilité flexible
  • Coûts d'investissement réduits
✗ Inconvénients :
  • Coûts d'infrastructure élevés
  • Maintenance interne complexe
  • Moins de flexibilité
  • Expertise requise
 ✗ Inconvénients :
  • Dépendance internet
  • Confidentialité des données
  • Dépendance au fournisseur
  • Coûts récurrents

Types de Services Cloud

SaaS (Software as a Service) : Logiciels accessibles par navigateur (Microsoft 365, Salesforce, Slack). Bénéfices : accès, mises à jour automatiques, pas d'installation.
PaaS (Platform as a Service) : Plateforme de développement (Heroku, AWS Elastic Beanstalk). Bénéfices : déploiement rapide, infrastructure gérée.
IaaS (Infrastructure as a Service) : Serveurs virtualisés (AWS EC2, Azure, DigitalOcean). Bénéfices : flexibilité, payez à l'usage, scalabilité.

Structure du Cahier des Charges Fonctionnel (CDCF)

1. Présentation du Contexte

Éléments : Description de l'organisation, contexte actuel, problématiques existantes, enjeux du projet.

2. Expression des Besoins

Besoins Métier : Ce que l'organisation veut accomplir (augmenter la productivité de 30%, réduire délais, améliorer satisfaction client).
Besoins Fonctionnels : Fonctionnalités requises (gestion de stock, facturation automatique, rapports personnalisés).
Besoins Non-Fonctionnels : Performance, sécurité, disponibilité (temps de réponse < 2s, uptime > 99%, sauvegardes quotidiennes).

3. Spécifications Techniques

Éléments : Architecture système, technologies, base de données, interfaces utilisateur, intégrations avec systèmes existants, sécurité.

4. Critères d'Acceptation

Éléments : Tests d'acceptation utilisateur (UAT), métriques de validation, conditions de succès, procédures de recette.

5. Planification et Délais

Éléments : Planning du projet, jalons importants, ressources allouées, budget estimé, risques identifiés.
💡 Exemple simplifié :
Besoin métier : "Améliorer le traitement des commandes"
Besoin fonctionnel : "Système de gestion de commandes web avec panier e-commerce"
Besoin non-fonctionnel : "Performance < 2s, sécurité HTTPS, 99.5% disponibilité"
Critère d'acceptation : "Traitement de 100 commandes/jour sans ralentissement"

Exercices Pratiques

Exercice 1 : Analyse d'un Besoin Cloud
Énoncé : Une PME manufacturière veut digitaliser sa gestion d'approvisionnement et stocker ses données dans le cloud. Analyse les critères : coûts annuels estimés à 50 000€, bénéfices attendus : réduction délais de 40% valorisée à 100 000€, moins 15 000€ de coûts IT interne.

Question : Calculez le ROI et décidez si la solution est intéressante financièrement. Lisez les 3 modèles cloud (SaaS/PaaS/IaaS) et proposez la meilleure option avec justification.

Correction :

Calcul du ROI :
  • Bénéfices totaux : 100 000€ - 15 000€ = 85 000€
  • Coûts : 50 000€
  • ROI = (85 000 - 50 000) / 50 000 × 100% = 70%

✓ Décision : ROI de 70% en 1 an est excellent. Le projet est financièrement viable.

Modèle recommandé : SaaS (ex: SAP SuccessFactors, Salesforce)

Justification :

  • Accès web accessible depuis n'importe où
  • Pas de maintenance serveur interne
  • Mises à jour automatiques
  • Scalabilité pour croissance future
  • Support professionnel du fournisseur
Exercice 2 : Rédaction de CDCF
Énoncé : Rédigez la section "Expression des Besoins" pour un projet de système de gestion de bibliothèque numérique avec :
  • Besoin métier : Centraliser le catalogue et simplifier les emprunts
  • Besoin fonctionnel : Catalogue searchable, système d'emprunt/retour, réservations
  • Besoin non-fonctionnel : Accès mobile, 99% uptime, temps recherche < 1s
Correction - Section Expression des Besoins :

2. EXPRESSION DES BESOINS

2.1 Besoins Métier
La bibliothèque souhaite :
  • Centraliser le catalogue de livres (actuellement sur 3 bases différentes)
  • Réduire les délais d'emprunt de 15 minutes (traitement papier) à 2 minutes (digital)
  • Permettre les réservations et notifications automatiques
  • Améliorer la satisfaction des usagers et élargir l'accès au public

2.2 Besoins Fonctionnels
Le système doit fournir :
  • Interface de recherche avancée (titre, auteur, ISBN, catégorie, année)
  • Système d'authentification des usagers
  • Processus d'emprunt/retour simplifié (code-barres ou QR)
  • Système de réservation avec notification par email
  • Rapports de gestion (livres empruntés, retards, popularité)

2.3 Besoins Non-Fonctionnels
  • Disponibilité : 99% uptime (max 8.76h downtime/an)
  • Performance : Recherche < 1s, page chargement < 2s
  • Accessibilité : Compatible mobile, responsive design
  • Sécurité : Chiffrement données personnelles (RGPD), authentification sécurisée
  • Scalabilité : Capacité pour 10 000 usagers simultanés
Exercice 3 : Grille de Critères de Choix
Énoncé : Vous devez choisir un outil de gestion de projets pour votre équipe IT de 15 personnes. Trois solutions sont candidates : Asana (Cloud SaaS), Microsoft Project (On-Premise), Jira (Open Source).

Question : Établissez une grille de critères pondérés pour comparer les trois solutions et déterminez la meilleure option.

Correction - Grille de Sélection :

Critère Poids Asana MS Project Jira
Facilité d'utilisation 30% 9/10 6/10 7/10
Coût annuel 25% 8/10 4/10 9/10
Fonctionnalités avancées 20% 8/10 9/10 8/10
Support/Documentation 15% 9/10 8/10 7/10
Intégrations disponibles 10% 8/10 7/10 9/10

Calcul du Score Pondéré :

  • Asana : (9×0.30) + (8×0.25) + (8×0.20) + (9×0.15) + (8×0.10) = 8.4/10
  • MS Project : (6×0.30) + (4×0.25) + (9×0.20) + (8×0.15) + (7×0.10) = 6.7/10
  • Jira : (7×0.30) + (9×0.25) + (8×0.20) + (7×0.15) + (9×0.10) = 7.9/10

✓ Recommandation : ASANA avec score 8.4/10. Meilleur rapport facilité/coût, excellent support, interface intuitive pour les équipes IT Agiles.

Exercice 4 : Migration Cloud
Énoncé : Votre entreprise souhaite migrer son système ERP (actuellement On-Premise depuis 2010) vers le cloud. Les options sont : SaaS complet, IaaS, ou maintenir On-Premise.

Questions :

  • Listez les critères de faisabilité à analyser
  • Comparez les 3 options (SaaS/IaaS/On-Premise) sur 5 critères clés
  • Proposez une recommandation
Correction :

1. Critères de faisabilité à analyser :
  • Technique : Compatibilité avec infrastructure actuelle, temps de migration, interruptions service
  • Financière : CAPEX vs OPEX, ROI 3-5 ans, coûts cachés
  • Organisationnelle : Acceptation utilisateurs, formations, changement processus
  • Sécurité/Conformité : RGPD, certifications, localité données
  • Vendeur : Support, SLA, stabilité financière

2. Comparaison des solutions :
Critère SaaS IaaS On-Premise
Coûts initiaux Bas ✓ Moyen Élevé ✗
Maintenance Minimal ✓ Modérée Complexe ✗
Customisation Limitée Complète ✓ Complète ✓
Disponibilité 99.99% ✓ À configurer À maintenir
Dépendance vendeur Élevée Modérée Nulle ✓

✓ Recommandation : SAAS (ex: SAP S/4HANA Cloud, Oracle Cloud)

Justification :

  • Coûts OPEX prévisibles au lieu de CAPEX massif
  • Mises à jour et maintenance gérées par le fournisseur
  • 99.99% de disponibilité garantie
  • Migration progressive possible sans interruption majeure
  • Support expert 24/7
