Management SI & Gestion de Projet

BTS SIO - Stratégie, Agile, GANTT, ITIL

1. Système d'Information dans l'Entreprise

SI (Système d'Information) : Ensemble ressources (hardware, software, données, personnes) pour collecter, traiter, diffuser informations. Aligné stratégie métier.
Direction Informatique : Responsable infra, sécurité, support utilisateurs. Budget IT = 30-40% budget général entreprise. CIO (Chief Information Officer) = responsable stratégique SI.
Gouvernance SI : Décisions investissements IT, risques sécurité, conformité réglementaire (RGPD, normes). Comité de direction valide projets majeurs.

2. Gestion de Projet : Cycle V vs Agile

Cycle V (Waterfall) : Linéaire : Analyse → Conception → Développement → Tests → Déploiement. Séquentiel, documenté. Risque : changements après développement coûtent cher. Approprié : projets prévisibles, requirements stables (ex: infra reseau).
Agile/Scrum : Itératif par sprints (2-4 semaines). Backlog → Sprint planning → Daily standup → Sprint review → Retrospective. Flexible changements. Approprié : projets innovants, requirements évolutifs (ex: app mobile).
Rôles Agile : Product Owner = définit backlog priorité, Scrum Master = facilite processus, Development Team = réalise sprint

3. Planning : GANTT et PERT

Diagramme GANTT : Visualise planning projet avec tâches, durées, dépendances sur axe temps. Montre chemin critique (tâches sans marge).
GANTT Exemple : Tâche A (1 sem) → Tâche B (2 sem) parallèle Tâche C (2 sem) → Tâche D (1 sem). Si A retard 1 sem = projet retardé 1 sem (chemin critique A→B→D).
PERT (Program Evaluation Review Technique) : Temps probabiliste : optimiste (3j), probable (5j), pessimiste (8j). Temps attendu = (O + 4×P + P) / 6 = (3 + 20 + 8) / 6 = 5.1j. Gère incertitude projets R&D.

4. ITIL - IT Service Management

ITIL (IT Infrastructure Library) : Best practices gestion services IT. V4 = 5 livres : Strategy, Design, Transition, Operation, Continual Improvement.
Concepts clés : Incident (interruption service), Problème (cause root incident), Changement (modification infra), Disponibilité (SLA 99.9%), Capacité (dimensionner ressources).
SLA (Service Level Agreement) : Contrat entre IT et client. Ex: "Disponibilité 99.9% (max 8.7h downtime/mois)", "Support 24/7", "Résolution incident Sev1 < 4h".

Exercices

Exercice 1 : Choisir méthodologie - Refonte ERP vs App mobile startup
Refonte ERP → Waterfall : Processus métier connus et stables, requirements définis avant (CDCF complet), gros investissement = pilotage strict.
App mobile startup → Agile : Feature set évolutif, market feedback itératif, MVP rapide (minimum viable product), pivots possibles.
Exercice 2 : Construire GANTT simple - Migration serveur
Semaine 1 : Analyse (3j) → Backup (1j, parallèle analysis)
Semaine 2 : Provisioning (1j) → Migration (2j, dépend backup) → Tests (2j)
Semaine 3 : Déploiement (1j) → Documentation (2j)

Chemin critique = Analyse (3j) + Backup (1j) + Migration (2j) + Tests (2j) + Deploy (1j) = 9j = 9-10 semaines total. Marge sur Provisioning car peut commencer avant backup fin.
Exercice 3 : Calculer durée PERT - Tests logiciel
Optimiste : 5 jours (tout bien), Probable : 10 jours (réaliste), Pessimiste : 20 jours (pb découverts)
Temps attendu PERT = (5 + 4×10 + 20) / 6 = (5 + 40 + 20) / 6 = 65/6 = 10.8 jours

Variance = ((20-5)/6)² = (15/6)² = 6.25 → écart-type = 2.5j
Intervalle confiance 95% : 10.8 ± 2×2.5 = [5.8 - 15.8 jours]
Exercice 4 : Calculer disponibilité SLA
SLA 99.9% signifie max downtime = 365×24×(1-0.999) = 365×24×0.001 = 8.76 heures/an
SLA 99.99% signifie max downtime = 52.56 minutes/an
SLA 99.999% (5-nines) = 26.3 secondes/an (très cher)

Exemple réel : Incident 2h non-planifié = 120 min > 8.76 h/12 mois = violation SLA Mensuel = pénalité financière client
Exercice 5 : Sprint Agile de 2 semaines - Listebacklog et célérité
Product Backlog (priorisé) :
1. Auth utilisateur (Severity: MUST - 8 points story)
2. Dashboard statistiques (SHOULD - 5 points)
3. Export PDF (NICE - 3 points)
4. Intégration SMS (SHOULD - 8 points)

Sprint Planning : Team capacity = 10 points/semaine × 2 = 20 points
Sprint Backlog = Auth(8) + Dashboard(5) + Export(3) + SMS prep(4 points) = 20 points

Daily Standup : Chaque 15 min - Fait hier? À faire? Blockers?
Sprint Review : Démo fonctionnalités complétées
Retrospective : Quoi améliorer ? Vélocité = 20 points réels / 20 estimés = 1.0 (bon)
