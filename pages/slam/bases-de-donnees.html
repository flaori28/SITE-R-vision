Modèle Entité-Association (MCD)

La modélisation des données est la première étape du design d'une base de données. Le MCD (Modèle Conceptuel de Données) représente les entités et leurs relations.

Éléments fondamentaux

Entité : Objet du monde réel auquel on s'intéresse (Client, Produit, Commande). Représentée par un rectangle.
Attribut : Propriété d'une entité (Nom client, Email, ID commande). Chaque attribut a un type de données.
Relation : Lien entre deux entités (Un Client PASSE plusieurs Commandes). Représentée par une ellipse.
Clé Primaire : Attribut qui identifie uniquement chaque occurrence d'une entité (ID Client, numéro de produit).
💡 Exemple MCD simple :
Entité CLIENT : (IdClient, Nom, Email, Téléphone)
Entité PRODUIT : (IdProduit, Nom, Prix)
Relation : CLIENT ACHÈTE PRODUIT (CardinalitéMin:1, Max:N)

Cardinalités

Cardinalité : Exprime le nombre d'occurrences minimum et maximum d'une entité dans une relation.
  • 0,1 : Au moins 0, au maximum 1 occurrence (optionnel)
  • 1,1 : Exactement 1 occurrence (obligatoire)
  • 0,N : Au moins 0, au maximum plusieurs (optionnel, multiple)
  • 1,N : Au moins 1, au maximum plusieurs (obligatoire, multiple)
Exemple : CLIENT (1,N) PASSE (1,N) COMMANDE signifie : Un client passe plusieurs commandes, une commande est passée par un seul client.

Du MCD au MLD (Modèle Logique)

La transformation MCD → MLD adapte le schéma conceptuel aux contraintes des SGBD relationnels.

Transformation des Entités

Règle 1 : Chaque entité MCD devient une table MLD avec ses attributs en colonnes.
-- Entité CLIENT du MCD
CREATE TABLE CLIENT (
  IdClient INT PRIMARY KEY,
  Nom VARCHAR(100),
  Email VARCHAR(100)
);

Clés Étrangères

Clé Étrangère : Attribut d'une table qui référence la clé primaire d'une autre table. Assure l'intégrité référentielle.

Exemple Complet : Gestion de Commandes

Table Attributs Description
CLIENT IdClient (PK), Nom, Email Informations clients
COMMANDE IdCommande (PK), DateCommande, IdClient (FK) Commandes avec lien client
PRODUIT IdProduit (PK), Nom, Prix Catalogue produits
LIGNE_COMMANDE IdLigne (PK), IdCommande (FK), IdProduit (FK), Quantité Articles d'une commande

Langage SQL de Base

SELECT - Interroger les données

-- Récupérer tous les clients
SELECT * FROM CLIENT;

-- Récupérer colonnes spécifiques
SELECT IdClient, Nom, Email FROM CLIENT;

-- Avec condition WHERE
SELECT * FROM CLIENT WHERE Email LIKE '%@gmail.com';

-- Ordre de tri
SELECT * FROM COMMANDE ORDER BY DateCommande DESC;

Agrégations et Groupement

-- Nombre total de commandes
SELECT COUNT(*) FROM COMMANDE;

-- Montant total par client
SELECT IdClient, SUM(Montant) as TotalClient
FROM COMMANDE GROUP BY IdClient;

-- Moyenne prix produits par catégorie
SELECT Categorie, AVG(Prix) as PrixMoyen
FROM PRODUIT GROUP BY Categorie HAVING AVG(Prix) > 100;

Jointures (JOIN)

INNER JOIN : Retourne les lignes qui ont une correspondance dans les deux tables.
-- Clients avec leurs commandes
SELECT C.Nom, COM.IdCommande, COM.DateCommande
FROM CLIENT C
INNER JOIN COMMANDE COM ON C.IdClient = COM.IdClient;
LEFT JOIN : Retourne toutes les lignes de la table gauche + les correspondances à droite.
-- Tous les clients (même sans commande)
SELECT C.Nom, COUNT(COM.IdCommande) as NbCommandes
FROM CLIENT C
LEFT JOIN COMMANDE COM ON C.IdClient = COM.IdClient
GROUP BY C.IdClient, C.Nom;

Mise à jour (INSERT, UPDATE, DELETE)

-- Ajouter un nouveau client
INSERT INTO CLIENT (IdClient, Nom, Email)
VALUES (5, 'Dupont Jean', 'jean@email.com');

-- Modifier un email
UPDATE CLIENT SET Email = 'nouveau@email.com'
WHERE IdClient = 5;

-- Supprimer un client
DELETE FROM CLIENT WHERE IdClient = 5;

Intégrité Référentielle

Intégrité Référentielle : Garantit qu'une clé étrangère ne peut référencer que des clés primaires existantes. Empêche les données orphelines.
CREATE TABLE COMMANDE (
  IdCommande INT PRIMARY KEY,
  IdClient INT NOT NULL,
  DateCommande DATE,
  FOREIGN KEY (IdClient) REFERENCES CLIENT(IdClient)
  ON DELETE CASCADE -- Supprime les commandes si client supprimé
);

Exercices Pratiques

Exercice 1 : MCD Bibliothèque
Énoncé : Modéliser une bibliothèque numérique avec Livres, Auteurs, Emprunteurs et Emprunts. Définissez les entités, attributs et cardinalités.
MCD Proposé :

Entité AUTEUR : (IdAuteur, Nom, DateNaissance)
Entité LIVRE : (IdLivre, Titre, ISBN, IdAuteur FK)
Entité EMPRUNTEUR : (IdEmprunteur, Nom, Email)
Entité EMPRUNT : (IdEmprunt, IdEmprunteur FK, IdLivre FK, DateEmprunt, DateRetour)

Cardinalités :
- AUTEUR (1,N) ÉCRIT (1,N) LIVRE : Un auteur écrit plusieurs livres
- EMPRUNTEUR (1,N) EMPRUNTE (1,N) LIVRE via EMPRUNT table
- Relation ternaire : EMPRUNT lie EmprunteuR, LIVRE, et date
Exercice 2 : Requête SQL avec Jointure
Énoncé : Écrivez une requête qui affiche le nom du client et le montant total de ses commandes, en triant par montant décroissant.
SELECT C.Nom,
  SUM(LC.Quantite * P.Prix) as MontantTotal
FROM CLIENT C
INNER JOIN COMMANDE COM ON C.IdClient = COM.IdClient
INNER JOIN LIGNE_COMMANDE LC ON COM.IdCommande = LC.IdCommande
INNER JOIN PRODUIT P ON LC.IdProduit = P.IdProduit
GROUP BY C.IdClient, C.Nom
ORDER BY MontantTotal DESC;
Exercice 3 : Correction d'Erreur SQL
Énoncé : Trouvez et corrigez l'erreur dans cette requête :
SELECT ClientID, SUM(Amount)
FROM ORDERS
WHERE Amount > 1000
GROUP BY OrderID;
Erreurs :
1. GROUP BY OrderID au lieu de ClientID (incohérence avec SELECT)
2. WHERE après GROUP BY devrait être HAVING

Correction :
SELECT ClientID, SUM(Amount)
FROM ORDERS
GROUP BY ClientID
HAVING SUM(Amount) > 1000;
Exercice 4 : Conception MLD Complet
Énoncé : Convertir le MCD d'une gestion de stock en MLD avec 3 tables : Produit, Stock, et Mouvements.
CREATE TABLE PRODUIT (
  IdProduit INT PRIMARY KEY,
  Nom VARCHAR(100),
  Prix DECIMAL(10,2)
);

CREATE TABLE STOCK (
  IdStock INT PRIMARY KEY,
  IdProduit INT UNIQUE NOT NULL,
  Quantite INT DEFAULT 0,
  FOREIGN KEY (IdProduit) REFERENCES PRODUIT(IdProduit)
);

CREATE TABLE MOUVEMENT (
  IdMouvement INT PRIMARY KEY,
  IdProduit INT NOT NULL,
  Type ENUM('Entrée', 'Sortie'),
  Quantite INT,
  DateMouvement DATE,
  FOREIGN KEY (IdProduit) REFERENCES PRODUIT(IdProduit)
);
Exercice 5 : Analyse avec GROUP BY HAVING
Énoncé : Trouvez tous les clients ayant passé plus de 5 commandes et un montant total > 5000€.
SELECT C.IdClient, C.Nom,
  COUNT(COM.IdCommande) as NbCommandes,
  SUM(COM.Montant) as MontantTotal
FROM CLIENT C
INNER JOIN COMMANDE COM ON C.IdClient = COM.IdClient
GROUP BY C.IdClient, C.Nom
HAVING COUNT(COM.IdCommande) > 5
  AND SUM(COM.Montant) > 5000
ORDER BY MontantTotal DESC;
